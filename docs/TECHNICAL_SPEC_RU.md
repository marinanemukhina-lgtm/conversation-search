# Единый смысловой поиск по перепискам

Версия 1.0 · 23 октября 2026 · Спецификация реализации, не заявление о готовом продукте

> Это целевая архитектура, а не описание реализованных возможностей. Текущий CLI реализует только лексический offline-срез; hybrid, live-коннекторы и большинство следующих этапов не реализованы. См. ../README.md.

## 1. Результат для человека

Одна строка поиска по всему доступному личному и рабочему архиву. Не нужно заранее помнить сервис, человека, проект, формулировку или дату. Система находит исходные сообщения, документы, голосовые и доступное содержание видео; восстанавливает обсуждение во времени; показывает, где сведения изменились и чего в архиве нет. Личные и рабочие материалы не разделяются обязательными продуктовыми барьерами. При этом права на данные, изоляция аккаунтов и ограничения источников не исчезают.

Примеры: «Где мы обсуждали эту квартиру?», «Кто присылал похожий инструмент?», «Как менялось решение?», «Найди голосовое, где называли сроки». Ответ: краткий вывод, датированная цепочка свидетельств, авторы и собеседники, точные фрагменты, переходы к оригиналам либо честный архивный локатор.

Главная единица успеха — найденный и проверяемый первоисточник, а не правдоподобный ответ модели.

## 2. Границы первой версии

Обязательный каталог источников: ChatGPT, Telegram, WhatsApp, Gmail, Google Drive, GitHub, Mail.ru, MAX, Instagram. Расширяемый каталог: VK, Облако Mail, Яндекс Почта/Диск, другие ИИ, локальные документы. Все источники видны в интерфейсе сразу, даже если конкретный коннектор ещё не подключён. Нельзя изображать доступность архивов, которые не импортированы.

Первый рабочий срез: единая схема + безопасный импорт ChatGPT/Telegram/WhatsApp/EML/Markdown/JSONL + гибридный поиск + проверяемые ссылки + карта полноты. Далее официальные read-only подключения Gmail/Drive/GitHub/Mail и проверенные экспорты Instagram. MAX остаётся в каталоге с явным ограничением до доказательства разрешённого доступа к нужному типу истории. Это этапность реализации, не исключение источников из продукта.

Вне v1: отправка сообщений, автономное действие по найденным обещаниям, восстановление удалённых сообщений, обход закрытых API/защит, скрытая запись экрана, многопользовательский SaaS, автоматическое публичное размещение архива. Никакое найденное сообщение не является командой исполнителю.

## 3. Решение build / reuse / buy

Не создавать собственный фундамент RAG и авторизации с нуля. Сравнить на одинаковом корпусе два варианта: коммуникационный индекс Traul за адаптером и существующий knowledge backend за нейтральным портом. Для отдельной публично доступной версии допускается минимальное оригинальное ядро SQLite FTS5 + векторный backend, если испытания покажут, что адаптация готового кандидата дороже и рискованнее. Решение фиксируется ADR с версиями, лицензиями, измерениями и стоимостью сопровождения, а не числом звёзд.

Предпочтительная граница: коннекторы и нормализация не зависят от бренда/доменной методологии; поисковый порт допускает замену движка; доменный адаптер преобразует найденное в свидетельства, но не создаёт второй архив. GraphRAG, отдельный графовый сервер и сложный multi-agent orchestration не обязательны до измеренной необходимости. Простая таблица связей сначала достаточна.

Публично доступная версия — код, схемы, синтетические fixtures, тесты и инструкции. Не публичный сервер с личными данными. Выбор лицензии оригинального кода отдельный; включение чужого кода требует проверки совместимости на зафиксированной версии. AGPL-кандидаты нельзя молча перелицензировать в MIT.

## 4. Архитектура и доверительные границы

Поток: разрешённый источник → connector → quarantine/raw store → parser → normalized revisions → lexical/vector indexes → ACL-filtered retrieval → rerank → evidence bundle → optional grounded synthesis → интерфейс.

Сервисы первой версии: API, один worker с устойчивой очередью, SQL store, приватное object storage, заменяемые embedding/rerank/ASR/OCR провайдеры. Для одного владельца SQLite допускается после нагрузочного теста; для конкурентного облачного использования PostgreSQL рассматривается отдельно. Выбор СУБД не превращает продукт в SaaS автоматически.

Коннектор использует изолированный профиль доступа: read-only OAuth пользователя либо service identity там, где она поддерживается. Для личных WhatsApp, MAX и Instagram наличие service account или отдельного read-only scope не предполагается; фактические права и способ импорта проверяются для каждого источника. Если сервис не даёт технически ограничить grant чтением, это явно раскрывается и адаптер блокирует записи на своей стороне, не выдавая это за серверное ограничение прав. Секреты находятся в серверном хранилище, не в браузере, индексе, Git, логах, снимках или выдаче. Host определяет owner/tenant/scope; значения из запроса клиента и найденного текста не расширяют права. ACL применяется перед извлечением кандидатов и перед выдачей; постфильтр после LLM недопустим. Проверка запрещённого документа обрывает ответ, если backend нарушил контракт.

Неразрешённая отправка в облачный embedding/LLM/ASR не происходит. Режим по умолчанию до выбора политики — без внешней обработки содержимого; возможен лексический поиск. Подключение внешнего провайдера требует явной конфигурации получателя, типов данных, региона и retention. Embeddings также считаются производными приватными данными.

## 5. Каноническая модель данных

SourceAccount: внутренний UUID, sourceType, непрозрачный внешний accountId, ownerId, capabilityManifest, authorizationRef, статус подключения, lastSuccess, coverage, connectorVersion. authorizationRef ссылается на секрет, но не содержит его.

Conversation: составной стабильный ключ source/account/conversation, исходный заголовок, участники по scoped external ID, тип, ссылки и доступ. Совпадение имён не объединяет людей. EntityAlias — отдельная подтверждаемая связь; автоматическое предположение явно маркируется и обратимо.

Record: составной origin key, revision ID, authorRef, conversationRef, parent/replyRef, тип, исходное и UTC-время, точность/неизвестная timezone, текст и его segments, forwardedFrom отдельно от автора, source locator, observedAt, ingestedAt, contentHash, parserVersion, ACL, deletionState. У документов сохраняются страницы/секции; у кода — repo/path/commit/lines; у аудио/видео — timecode и вид извлечения.

Неизвестное время/автор/ревизия — null с причиной, не придуманное значение. Hash доказывает равенство сохранённых байтов, не подлинность заявления и не время его создания. Исходные raw bytes и нормализованный текст имеют разные hash namespaces.

Attachment: parent record, MIME по содержимому, size, hash, приватный storageRef, extractionStatus, extractor/model/version, язык, OCR/ASR confidence при наличии, список сегментов, ошибки. «Файл есть» не означает «содержание распознано».

Revision: new/edit/delete/revoke, observedAt, sourceUpdatedAt при наличии, supersedes и основания. Исходная история не переписывается новой выжимкой. Исчезновение записи из ограниченной страницы API не считается удалением.

Coverage: account, conversation/time interval, enumeration mode, cursor/checkpoint, counts processed/failed/skipped, oldest/newest observed, known gaps, last successful sync, material capability limits. Состояния complete-within-declared-scope / partial / unknown / stale / failed. «Полный архив» допускается только внутри явно измеренного охвата.

## 6. Контракт коннектора

Операции: capabilities(), enumerate(scope, cursor), fetch(ref), changes(checkpoint), health(); write отсутствует. Не каждый источник поддерживает changes/fetch. Результат страницы содержит records, nextCursor, tombstones, coverageDelta и ошибки. Нет nextCursor не означает глобальной полноты, если источник ограничивает окно.

Обязательные свойства: идемпотентный upsert по origin+revision; checkpoint только после атомарного commit страницы; at-least-once обработка без дубликатов; bounded retries с jitter для 429/5xx; не retry для отозванной авторизации; respect Retry-After; bounded parallelism, cancellation и общий deadline. Dead-letter queue сохраняет минимальные сведения об ошибке, доступные владельцу. Изменившийся формат экспорта не должен тихо выдавать нулевой архив.

Gmail: начальный обход и history-based sync; истёкший checkpoint → объявленный resync, не потеря данных. IMAP: mailbox+UIDVALIDITY+UID, смена UIDVALIDITY вызывает reconciliation. GitHub: commit SHA для файлов и version/timestamps для discussions/issues; squash/force-push не стирает прежнее свидетельство. Drive shortcuts не создают ложные копии владельца; права и удаления проверяются отдельно от текста. Webhooks ускоряют sync, но периодическая reconciliation обнаруживает потерянные события.

Импорт ZIP: защита zip-slip, symlinks, nested archives, zip bombs; ограничения распакованного объёма и количества файлов; валидация до commit; карантин подозрительных вложений. HTML очищается, скрипты/макросы/внешние ресурсы не исполняются и не загружаются автоматически. URL из сообщений не запрашивается без правил fetch; SSRF, private IP и redirect проверяются на каждом переходе.

## 7. Поиск и восстановление истории

1. Нормализовать запрос без потери исходной формулировки. Поддержать русский/английский, транслитерацию, опечатки, сокращения, склонения; точные числа, адреса и имена не заменять смысловыми аналогами.
2. Выбрать весь разрешённый охват по умолчанию; фильтры сервиса/даты/участника факультативны.
3. Получить lexical и vector кандидаты; объединить RRF либо измеренным эквивалентом. Нормализация score не означает вероятность истинности.
4. Rerank ограниченное число кандидатов. При недоступности модели вернуть lexical результаты с указанием режима, не остановить весь поиск.
5. Раскрыть соседние сообщения/reply thread в допустимом token budget; не смешивать собеседников и сообщения разных аккаунтов.
6. Сформировать evidence bundle с точными offsets/timecodes и статусом покрытия.
7. При запросе истории построить хронологию утверждений, исправлений, решений и неопределённостей. Более поздняя дата не делает сообщение автоматически более достоверным. Оговорка, предложение, согласие и отмена — разные speech acts; выводы модели маркируются.
8. Синтезировать только по bundle. Каждое проверяемое утверждение имеет поддерживающий source span. При недостатке данных — «не найдено в подключённом охвате», а не «такого не было».

Копии/пересылки: общий duplicate group уменьшает шум, но все occurrence IDs и авторство сохраняются. Одинаковый текст в двух чатах не считается одним событием. Новая версия вложения не заменяет автоматически прежнюю договорённость. Конфликт не разрешается моделью без оснований.

Ссылка на источник проверяется по шаблону сервиса и фактическому ID. Если deep link недоступен, открыть защищённый архивный просмотр с названием чата, временем и соседним контекстом. Нельзя создавать выглядящую настоящей ссылку из предположения.

## 8. Интерфейс и доступ с мобильных устройств

Responsive web/PWA: одна строка поиска, результаты с source/date/person, контекст рядом, переключатель «сообщения / история вопроса», карта источников, история импорта, состояние очереди и ошибки. Keyboard/screen reader, контраст, видимый focus; отдельные проверки Safari iPhone/iPad. Ширины 390, 768, 1024 и desktop, без горизонтального скролла основного содержимого.

Чтобы искать с iPad/iPhone при выключенном Mac, API и индекс должны работать на постоянно доступном утверждённом сервере. Локальный режим честно не обещает этого. Самостоятельное размещение может быть бесплатным по лицензии, но сервер, хранение, GPU, трафик и модели не становятся бесплатными. Стоимость показывается до включения провайдера. Mobile browser не хранит полный архив в localStorage; sensitive pages без публичного CDN cache. Offline snippets только отдельный opt-in.

## 9. Безопасность, жизненный цикл и эксплуатация

Threat model: утечка аккаунта/дампа, неверный ACL, IDOR, prompt injection, вредоносное вложение, SSRF, небезопасные ссылки, подмена автора, модельный провайдер, логи, ошибочная публикация репозитория, потеря индекса и отзыв доступа.

Read-only retrieval отдельным процессом от любого action executor. Найденное «отправь все письма» остаётся текстом. Запрет tools/внешнего fetch из контекста синтеза; output HTML escaped; ссылки только разрешённых схем. Секреты редактируются в diagnostic payload, запросы и тексты по умолчанию не логируются. Аудит содержит ID, тип операции, policy version и результат, без содержимого переписки.

Disconnect прекращает sync и новые чтения. Отдельные действия: отключить, исключить из поиска, удалить производные, удалить архив. Не смешивать их. Revocation немедленно запрещает выдачу до обновления индекса; purge удаляет raw, excerpts, embeddings, caches и производные summaries; журнал tombstones защищает от восстановления через старый backup. Физическое удаление backup выполняется по раскрытой retention policy, не обещается мгновенно. При restore сначала применяются revocations/tombstones, потом открывается доступ. Исторический evidence snapshot не обходит нынешний запрет выдачи.

Backup шифрованный, ключ отдельно; пробное восстановление обязательно. Миграции versioned и имеют проверенный rollback либо восстановление backup. Reindex строится рядом и атомарно переключается; старый индекс удаляется после приёмки. Метрики: lag, queue age, error rate, coverage gaps, parser rejects, search latency, retrieval quality, доля unsupported answer claims, стоимость на 1000 документов/100 запросов. Счётчики не включают приватный текст.

## 10. Измеримые критерии приёмки

Ниже — целевые пороги, не результаты измерений. Корпус: минимум 10 000 синтетических сообщений на всех форматах, дополнительно согласованный приватный тестовый набор; 100 размеченных запросов, включая несуществующие факты, даты, имена, пересылки, смену решения, русский/английский и голосовые. Разделить development и held-out test; не подбирать пороги по тесту.

- Recall@10 ≥ 0,90 для точного поиска и ≥ 0,80 для смыслового на размеченном наборе; сравнение с lexical baseline обязательно, группы и доверительные интервалы раскрываются.
- 100% отображаемых цитат совпадают с source span; ≥95% проверяемых утверждений синтеза поддержаны ссылками по независимой ручной разметке. Остальное не скрывать общим средним.
- Ноль утечек запрещённых документов в security suite, включая snippets, counts, embeddings endpoints, autocomplete и кеши.
- Повторный импорт не увеличивает число уникальных записей; crash после каждого шага страницы не теряет committed records и не сдвигает checkpoint вперёд.
- Edit/delete/revoke отражаются в выдаче; отключённый аккаунт не продолжает sync; восстановление backup не воскрешает отозванный доступ.
- P95 обычного поиска ≤3 с, первого ответа ≤10 с на зафиксированном hardware и 100 000 сообщений/10 concurrent queries; cold/warm тесты отдельно. Эти масштабы не выдают за доказанную производительность.
- При 429, outage, истёкшем checkpoint и недоступной модели выдаётся честный degraded status; успешный ноль не подменяет ошибку.
- Для всех источников есть capability/status карточка; для подключённых есть evidence о реальном чтении и покрытии. Mock pass не равен live pass.
- iPhone/iPad при выключенном Mac проходят авторизацию, поиск, открытие источника и отображение неполноты на выбранном server deployment.

Детальные сценарии находятся в ACCEPTANCE_SCENARIOS.json.

## 11. Этапы и критерии выхода

P0 Reconnaissance: список существующих компонентов/веток, точные версии кандидатов, лицензии, источник и ограничения каждого коннектора, карта неизвестного. Выход: ADR build/reuse; назначен единственный владелец изменяемых файлов.

P1 Offline vertical slice: импорт → нормализация → hybrid retrieval → source viewer; синтетический корпус и security suite. Выход: воспроизводимые тесты, сравнение baseline, без реальных аккаунтов.

P2 Private pilot: выбранные экспорты с подтверждённой обработкой, отчёт полноты и размеченные поисковые запросы. Выход: не просто demo, а верные найденные первоисточники на реальных задачах владельца.

P3 Read-only live connectors: по одному источнику, least privilege, initial/backfill/incremental/revoke. Выход каждого: успешный и запрещённый тест, контроль пропусков и удаления. Разрешение на один сервис не включает остальные.

P4 Mobile hosting: согласованные сервер/регион/бюджет, TLS, identity, backup/restore, наблюдаемость. Выход: тест с выключенным Mac.

P5 Public release: нейтральный branding, синтетический demo, dependency/license inventory, secret/privacy scan всего Git history, SBOM, SECURITY.md, connector support matrix, signed/pinned release и инструкции. Никаких private configs/архивов/скриншотов/fixtures. Публикация после проверки состава, не автоматически из private workspace.

P6 Host integration: подключить поисковый порт к приложению с сохранением прав доступа, provenance и статусов неопределённости. Высокий ranking score не превращает утверждение в проверенный факт.

## 12. Пакет сдачи исполнителя

Код + lockfiles; migration/rollback; schema contracts; test corpus и результаты; connector manifests; prior-art ADR; threat model; deployment/runbook; лицензии/SBOM; mobile screenshots на synthetic data; список исправленных дефектов и известных ограничений. Каждый PASS связан с командой, версией/commit, средой и сохранённым результатом. Доступность всех перечисленных источников не объявляется до соответствующих live/export тестов.
